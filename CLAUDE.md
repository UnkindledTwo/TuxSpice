# CLAUDE.md

## Project

**TuxSpice** is a native Linux, LTspice-compatible schematic capture and waveform viewer
(PySide6 + pyqtgraph + numpy) in `pyltspice/` (package and command are still named `pyltspice`).
It reads and writes LTspice `.asc`/`.asy` files and simulates with **ngspice**, not LTspice.
`README.md` (top level) is the user-facing description; keep its feature list, compatibility numbers,
comparison table (vs LTspice, ngspice, KiCad) and limitations in sync.
Positioning: TuxSpice is an LTspice work-alike for Linux. Files stay LTspice files, it uses LTspice's
libraries, UI and dialect, and ngspice runs underneath via a translation layer. It's not a KiCad-style
suite (no PCB) and not a new simulator.

- `LTspice64.msi`: the user's own LTspice installer. Its symbol/model libraries, examples and
  help are extracted locally and never redistributed or committed.
- `work/`: scratch output from batch sims (`*.ngspice.cir`, `*.log`, `*.raw`, screenshots). It is disposable.
- `.venv/`: the project virtualenv. Use `../.venv/bin/python` from inside `pyltspice/`.

## Layout (`pyltspice/pyltspice/`)

- `config.py`: data paths. Library at `~/.local/share/pyltspice/ltspice_lib` (`lib/sym`, `lib/sub`,
  `lib/cmp`, `examples`, `help`); symbols TuxSpice generates in `<data>/sym/AutoGenerated` (`USER_SYM_DIR`,
  searched by the symbol library). Env overrides: `PYLTSPICE_DATA`, `PYLTSPICE_LIB`, `PYLTSPICE_NGSPICE`,
  and `PYLTSPICE_NGSPICE_MEM` (GB per ngspice run, read by `runner.memory_limit`).
- `model/`: file formats and the data model: `asc.py` (schematic load/save, round-trips byte-for-byte
  modulo normalization), `asy.py` (symbols), `library.py`, `netlist.py` (schematic → SPICE netlist),
  `edit.py` (edit ops / undo), `geometry.py`, `textio.py` (encoding detection), `pcbnetlist.py`
  (Tools > Export Netlist).
- `sim/`: `ltcompat.py` translates LTspice netlist dialect → ngspice (parasitics like Rser/Cpar,
  1-arg `.tran`, `.lib`, default models, dropped options/params, µ suffix). Device emulation lives in
  `adevices.py` (A-devices, switches, ideal diodes, VDMOS, IGBT), `laplace.py`, `magnetics.py`
  (hysteretic core, `Flux=`), `wavefile.py`. `runner.py` runs ngspice with `set ngbehavior=ltpsa` +
  binary raw output and implements `.step` itself. `measure.py` evaluates `.meas` in Python after the
  run (ngspice never sees them). `rawfile.py` parses `.raw`; `vectors.py`, `spicenum.py`, `fft.py`,
  `pltfile.py` handle names, numbers, FFT and plot settings.
- `ui/`: Qt GUI. `main_window.py` is the entry point; `menus.py` holds LTspice's three menu bars
  (no window / schematic / waveform) and both right-click menus as data; `settings_dialog.py` is
  Tools > Settings (LTspice's ten tabs plus a TuxSpice tab of `tux/*` keys, `SPEC` lists every key with its default and whether LTspice
  remembers it, i.e. shows [*]); plus `schematic_window`/`schematic_view`/`items`/`tools`
  (editing), `waveform.py` (pyqtgraph plots), dialogs, `theme.py` (LTspice default colors, saved in QSettings),
  `appearance.py` (light/dark window palettes; icons are lightened for contrast on dark toolbars).
- `mcp/`: MCP server for AI assistants, mirroring LTspice 26.1's `ltspice-mcp-bridge` (tool names,
  arguments and string-valued JSON replies were captured from the real bridge under Wine). `bridge.py`
  is the stdio server (`pyltspice-mcp`, `python -m pyltspice.mcp`); it attaches to a running window
  through `ui/mcp_host.py` (127.0.0.1 + token, registry files from `registry.py`) or runs
  `headless.py`. `tools.py` has the schemas and the backend-independent logic; `clients.py`
  writes AI tools' MCP config (Tools > Configure Third-Party AI Assistants, `ui/ai_dialog.py`).
  Nothing may print to stdout in the bridge (it is the protocol stream). Replies must stay
  byte-compatible with LTspice's (compact sorted JSON, string scalars, its error texts): after any
  MCP change run `scripts/mcp_diff.py` against LTspice under Wine (`run lt`, `run tux`, `compare`).
- TuxSpice extras (not in LTspice; listed in README "What TuxSpice adds" and ui_spec "TuxSpice extras"):
  `model/check.py` (circuit check), `sim/diagnose.py` (ngspice errors explained), `ui/problems.py`
  (Problems dock), `sim/wavemeasure.py` + `ui/wavepanel.py` (measurements, step legend, histogram),
  `ui/plot_export.py`, `sim/libimport.py` + `ui/model_import.py` (vendor .lib → symbol),
  `ui/autosave.py`, `ui/notify.py`. Their settings are `tux/*` keys on Settings' 11th tab.
  Keep them out of the MCP path (replies must stay byte-compatible with LTspice's).
- `clonegen/`: behavioural clones of encrypted models. `inventory.py` (encrypted file → symbols,
  pins, family from the description, examples), `roles.py` (pin names → roles per channel: VIN, SW,
  FB, EN/UV, TR/SS...), `ltspice.py` (batch runs in LTspice under Wine), `bench.py` (an example
  netlist as a bench: run it in LTspice and ngspice, measurements), `fit.py` (benches and parameter
  extraction), `buck.py` (step-down template), `report.py` (overlay PNGs). Output:
  `config.CLONE_DIR` (`<data>/clones/<file>` + `<file>.json` with the raw measurements, so a
  template change is re-applied without LTspice: `fit.write_clone(part, meas)`).
- `data/`: TuxSpice's own parts (package data, not from LTspice): `models/tuxspice.{bjt,dio,mos,jft}`
  cards and `tuxspice_opamps.lib` (one behavioural core, `TUX_OPAMP`, per-part params) for common
  parts LTspice lacks, plus `sym/OpAmps/*.asy`. Fitted to datasheet typicals; `tests/test_models.py`
  simulates every part against those numbers, so add a row there with each new part.
  `setup_lib.py` + `ui/setup_dialog.py`: first-run extraction of the user's `LTspice64.msi`.
- Entry points: `pyltspice` → `pyltspice.app:main` (also `python -m pyltspice`); it starts the MCP
  host unless `PYLTSPICE_NO_MCP` is set. `pyltspice-mcp` → `pyltspice.mcp.bridge:main`.

## Setup

```sh
python3 scripts/extract_msi.py ../LTspice64.msi   # needs 7z (p7zip-full)
```
ngspice comes from the system (`/usr/bin/ngspice`) unless a bundled copy is found in the data dir.

## Commands (run from `pyltspice/`)

```sh
../.venv/bin/python -m pytest -q                      # full suite, ~15 s (round-trips every example .asc)
../.venv/bin/python -m pytest -q tests/test_sim.py    # run a single file while iterating
../.venv/bin/pip install -e .                         # after changing pyproject.toml / entry points
timeout 60 ../.venv/bin/python scripts/sim_example.py ../work <asc>  # headless netlist+sim, OK/FAIL
../.venv/bin/python scripts/sweep_examples.py ../work/out.tsv [--static] [--mem GB] <dir|asc...>  # parallel sweep: OK/FAIL/TIMEOUT/ENCRYPTED, resumable; jobs sized to free RAM
../.venv/bin/python scripts/render_png.py <asc> <png>           # render schematic to PNG
QT_QPA_PLATFORM=offscreen ../.venv/bin/python scripts/gui_smoke.py ...  # drive GUI headlessly + screenshot
../.venv/bin/python scripts/install_desktop.py [--remove]      # launcher, icon, .asc/.raw association (~/.local/share)
```

## Testing notes

- `tests/conftest.py` forces `QT_QPA_PLATFORM=offscreen`, points `XDG_CONFIG_HOME` at a temp dir (so
  tests never touch the user's `~/.config/pyltspice`), and has a session `qapp` fixture. Any new
  script that opens `MainWindow` must do the same (see `scripts/gui_smoke.py`).
- `needs_lib` / `needs_ngspice` markers skip tests when the extracted library or ngspice is missing.
- `test_asc.py` round-trips **every** example `.asc` in the extracted library, so `.asc` writer changes must preserve it.
- To check visual changes, render them to PNG (`render_png.py` / `gui_smoke.py`) and look at the image.
  Don't rely only on the tests.
  Check dark themes too: the user's desktop is GNOME-based with a dark GTK theme; render with
  `QT_QPA_PLATFORMTHEME=gtk3` (offscreen still works) and let layout settle before grabbing.
- `tests/` is a package (`__init__.py`); test modules import helpers via `from .conftest import ...`.
- GUI tests hang on any modal: right-click in idle mode opens a context menu (`QMenu.exec`), and
  closing a modified schematic asks to save. Leave modes with right-click only while a tool is
  active, and call `doc.undo.setClean()` before `win.close()`.
- Commands that share a key (A, C, D, P, B, Del, Ctrl+Z... mean different things in schematic
  and plot windows, as in LTspice) are separate actions with the same key, each enabled only for
  its window kind (`_act(on=...)`). Never enable both at once, or Qt treats the key as ambiguous.
  Anything that changes what's enabled must end in `_update_actions()` (plots emit `traces_changed`).
- Netlist pin order follows `SpiceOrder` after rotation, e.g. an R90 resistor nets as `R1 <right> <left>`.
- Orientations: `Mn` means rotate by n, *then* mirror x (M90 maps (x, y) → (y, x)). Verified against
  wire ends in `IdealTransformer.asc`; `test_mirrored_rotated_part_connects` guards it.
- Connectivity follows LTspice: a wire running under a component is cut at its pins, and the piece
  between two pins of the same part is ignored (`netlist._effective_wires`).
- Hierarchy: a symbol is a hierarchical block only if its `.asy` sits next to a same-named `.asc`
  (library symbols never are; `examples/Educational/opamp.asc` once became a subckt of itself).
- Keep every experiment short: the user does not want to wait on long timeouts. Cap ad-hoc sims at
  ~30 s (`timeout 30`, `.tran` shortened) and run sweeps in the background with a per-file `timeout 60`.
- A sim killed by `timeout` can't clean its `/tmp/pyltspice-*` work dir, and long runs write
  gigabytes (a sweep once filled the disk). Use `sweep_examples.py`, which gives each run its own
  TMPDIR, kills the whole process group and deletes it; otherwise clean up after killed runs.
- Autosave copies go to `$XDG_STATE_HOME/pyltspice/autosave`; conftest and `gui_smoke.py` point it at
  a temp dir. Any new script that opens `MainWindow` must too, or it may write real recovery files.
- `QWidget.render(painter)` needs a target offset in PySide6 (`render(p, QPoint())`); to render a
  plot at higher resolution, render into a QImage with `setDevicePixelRatio(k)` (a scaled painter crashes).
- MCP tests set `XDG_RUNTIME_DIR` to a temp dir so they never see (or attach to) a real TuxSpice
  window; GUI-attached tests run the bridge in a thread while the main thread pumps Qt events.
  Never let tests write a real AI tool config: point `HOME`/`XDG_CONFIG_HOME` at tmp first.
- The machine has 15 GB RAM and no swap: a runaway ngspice (LT6106.asc reached 13 GB) makes the OOM
  killer take the terminal down too. `runner._limit_memory` caps every ngspice at 60% of MemAvailable
  (`PYLTSPICE_NGSPICE_MEM=<GB>` overrides); `sweep_examples.py --mem` caps each job lower. Don't
  launch ngspice directly in parallel loops without `ulimit -v`.
- Never `pkill -f`/`pgrep -f` with a pattern that also appears in your own command line (it kills the
  shell running it). Use `pgrep -x ngspice`.

## Constraints

- UI parity with LTspice is clean-room: match it from the bundled help (`help/*.htm`) and by observing
  LTspice under Wine. Never decompile or disassemble `LTspice.exe`, and don't copy its bitmaps
  (toolbar icons are drawn in `ui/icons.py`). The app is TuxSpice, never "LTspice".
- Where LTspice behaviour is undocumented (e.g. PHASEDET), infer it from parameter names and the
  examples, say so in the docstring, and verify the direction/sign with a test.
- About 3k of the ~5k files in `lib/sub` are encrypted ADI models (`<Binary File>` header). Never try
  to decrypt them. 3322 of the 4365 bundled examples depend on one. They are being replaced by
  behavioural *clones* (`clonegen/`, below): black-box fits to what the encrypted model does when
  the user's own LTspice runs it. `ltcompat.clone_for` includes `<data>/clones/<file>` in place of
  the encrypted file when one exists; otherwise it's still reported as unsupported
  (`ltcompat.scan_definitions`). Clones are generated locally, like the extracted library, and
  never committed or redistributed.
- Every LTspice `A` device type in `lib/sym` is emulated in `sim/adevices.py` (OTA as B sources;
  gates, flip-flops, PHASEDET and COUNTER via XSPICE; Schmitt/S&H/VCO/varistor behavioural). The
  differential Schmitt symbols netlist as plain SCHMITT with in+/in- on pins 1/2. COUNTER is
  undocumented and unused in the examples: it's modelled as a divide-by-`cycles` (`d_fdiv`).
- `.pz` and `.disto` are ngspice-only extras (LTspice has neither): `.pz` results open in a table,
  `.disto` gives one plot window per harmonic (`PlotWindow.slot`), and probes go to all of them.

## Comparing with LTspice under Wine

- Run LTspice on a nested X server (`Xephyr :5`) in a *copy* of the Wine prefix with `LTspice.ini`
  removed, so the user's own settings are never touched. TuxSpice can run on the same display and
  be driven with the same XTest input; XFixes gives the cursor image. Results go in `docs/ui_spec.md`.
- LTspice crashes on exit under Wine (settings aren't saved), and its file dialogs don't open there.
  Open a schematic by passing it on the command line (`wine LTspice.exe "Z:/path/x.asc"`).
- Run Xephyr without a compositing window manager (none, or `metacity --no-composite`): with
  compositing, `xwd -root` shows stale contents. Menus and other popups never appear in
  `xwd -root`; capture each popup with `xwd -id <id>` (ids from `xwininfo -root -tree`).

## Running LTspice for clone fitting (`clonegen/ltspice.py`)

- Batch runs (`LTspice.exe -b x.net`) use a private copy of `~/.wine` at
  `<data>/clonegen/wine` (`ensure_prefix`). That copy *keeps* `LTspice.ini`: without it LTspice
  opens a modal "Anonymously Share LTspice Usage Data" prompt and `-b` hangs forever. It uses Wine's
  null graphics driver (`HKCU\Software\Wine\Drivers Graphics=null`), so no X server is needed.
- Several LTspice runs can share the prefix (4 in parallel ≈ 2.3× throughput). Each run gets its
  own dir under `<data>/clonegen/runs`, deleted afterwards. Add `.save` lines: an unrestricted
  2 ms switcher run writes ~80 MB of `.raw`.
- TuxSpice's own netlists (`generate_netlist`) run in LTspice unchanged once `µ`/`§` are made ASCII
  (`bench.ltspice_ascii`), so one netlist serves as both the reference and the test.

## Behavioural templates (lessons from `buck.py`)

- Relaxation oscillators built from tanh latches find a stable DC/transient equilibrium halfway
  through the transition. Clock with XSPICE `d_osc` (control = f in MHz) through a ≥1 ns
  `dac_bridge`: its edges are breakpoints, so no cycle is stepped over. Hold integrator nodes at 0
  during the operating point (`time>0 ? ... : -V(x)`), or they sit at f·R.
- Latches need a bistable hold term (`sig((s-0.5)*20)`), and their blanking must not depend on the
  latch itself (blank from the clock ramp), or a reset can stall halfway.
- Power switches need break-before-make gates (low side off below s=0.2, high side on above 0.8):
  partial overlap is shoot-through, which retriggers the current limit and collapses the time step.
- Never gate a conductance by its own terminal voltage (`V*g*sig(-V)` has negative resistance);
  diode emulation is a per-cycle zero-current latch.
- Extra breakpoint "tick" oscillators to catch the peak-current crossing cost 2.5× run time and
  didn't remove the jitter. They were dropped.

## ngspice quirks handled in `sim/`

- numparam has no `pi`: `translate()` prepends `.param pi=...`.
- `lib/cmp/standard.*` and some libraries are UTF-16 with no BOM. `textio.decode` sniffs this.
- Included libraries are rewritten (`ltcompat.ngspice_readable`) into `<data>/cache/libs`: A-devices,
  `table()`, parasitics, LTspice switch extensions, `.param` syntax, inline `;` comments,
  undeclared subckt params. Bump `LIB_CACHE_VERSION` whenever the rewrite changes, or stale copies are used.
- `.lib file` (no section) becomes `.include "<abs path>"`, and paths are resolved case-insensitively.
- ngspice reads `.spiceinit` from its cwd, so the runner works in a temp dir that holds one.
- Device currents come back as `i(@q1[ic])` and `v1#branch`. `vectors.lt_name` maps them to
  LTspice names (`Ic(Q1)`, `I(V1)`).
- X-instance rule (`netlist.element_line`): when SpiceModel names a model, use it plus Value2 (and
  Value too if it holds parameters, e.g. LTC1068-200's `Fclk=2Meg`). When SpiceModel is a *file*,
  Value2 is the subckt name plus params. Otherwise use Value, then Value2.
- LTspice functions ngspice lacks (`u`, `uramp`, `buf`, `inv`, `mc`, `flat`, `gauss`, `rand`, `random`,
  `white`) are added as `.func` only when used (`LT_FUNCS`, dependencies in `FUNC_DEPS`).
- Model cards are scoped per `.subckt` (`adevices.scoped_models`): LTC.lib defines e.g. `.model X D(...)`
  inside many subckts with different parameters. Any new model-based rewrite must use it.
- LTspice ideal diodes (Ron/Roff/Vfwd/Vrev/epsilon) become B sources with a C1 quadratic knee and no
  leakage tail (a softplus tail swamped µA-level macro-model nodes). Switch extensions likewise.
- VDMOS: drop the 4th node (ngspice reads extra nodes as thermal), and default Cgdmax/Cgdmin/Cgs/Cjo
  to 0 as LTspice does (ngspice's defaults load macro-model output stages).
- Smooth everything: hard ternary switches, 1 ps digital edges and threshold-exact XSPICE inputs
  stall ngspice's time step. Use tanh/quadratic transitions, ≥1 ns DAC edges, hysteresis latches.
- XSPICE `s_xfer` takes its DC state from `int_ic` instead of solving it, so Laplace sources are
  built as integrator chains instead (`laplace.to_elements`).
- ngspice leaves R/C/L currents (`@r1[i]`) at zero in `.ac`. For netlists with `.ac` the runner puts a
  0 V `v__isense_<dev>` source at each top-level R/C/L's first pin (`runner.add_ac_current_probes`);
  `rawfile.merge_sense_currents` copies them into `i(@r1[i])` and `vectors.lt_name` hides the helpers.
- K = 1 (perfect coupling) is clamped to 0.9999; ngspice's inductance matrix is singular otherwise.
- `G n+ n- nc+ nc- gm vto=<V> dir=1` (undocumented, ~570 uses in LTC.lib/ADI macro-models) is a
  one-sided clamp: a B source gm*knee(V(nc)-vto) (`ltcompat._threshold_vccs`).
- `I n+ n- <value> load` becomes `I0*tanh(V/0.25)` per the help page (`_load_current_source`).
- Symbols that skip SpiceOrder numbers (e.g. ADG919: 1-5, 8) get unconnected nodes in the gaps so
  the subckt port count matches (`netlist._fill_order_gaps`).
- numparam has no temperature: `temp`/`temper` inside `{...}` and `.param` become `lt_temp`
  (defined from `.temp`, default 27). B-source equations keep `temper`, which works there.
- `smallsig()` becomes `{lt_smallsig}`, set to 1 for `.ac`/`.noise` runs. Nested braces
  (`{a*{b}}`, common after `table()` expansion) are flattened to parentheses.
- Device currents in B/E/G expressions (`Id(M3)`, `Ic(Q1)`, `I(R5)`) get a 0 V sense source in
  series with that terminal, per subckt scope (`ltcompat.rewrite_device_currents`).
- Behavioral `R n+ n- R=<expr with V()/I()/time>` and `C ... Q=<expr>` become B sources.
  `NoJacob` on B sources is dropped. Model parameters may be comma-separated (`D(Ron=1k, Roff=1T)`).
- Non-ASCII characters in netlists/libraries (`M§Q6`, `10Ω`) are mapped to ASCII (`ascii_only`);
  ngspice rejects them.
- Non-converging runs are retried with relaxed options, each retry capped at `RETRY_TIMEOUT` (30 s).
